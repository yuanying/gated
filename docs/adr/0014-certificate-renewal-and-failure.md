# 0014. 証明書の更新判断と失敗時の扱い

- Date: 2026-08-21
- Status: Accepted

## Context

ADR 0005 は ACME クライアントを内蔵すると決め、「更新のタイミング、失敗時の挙動、有効期限が切れたときの応答をどうするかは実装時に詰める」と書いて、そこを空白のまま残した。決まっていたのは「更新に失敗しても既存の有効な証明書を使い続けること」だけである。

詰めるべきことは3つある。いつ更新するか、更新すべきかどうかを何から判断するか、そして更新できなかったときに何を書き換えないか、である。

3つ目が一番厄介である。「失敗しても使い続ける」は、失敗の経路で既存の Secret を触らないという形でしか保証できない。途中まで書いてから失敗する経路が1つでもあれば、その保証は崩れる。

## Decision

### 判断は純関数にする

更新すべきかどうかを、証明書の PEM・必要なホストの集合・現在時刻の3つだけを入力とする関数として書く。Kubernetes の型は入力に現れない（ADR 0007）。

出力は真偽値ではなく、**「更新すべきか」と「いま使えるか」の2つ**である。残り1週間の証明書は両方に当てはまる。更新しなければならないが、更新が届くまでは現に使える。この2つを1つの答えに畳んでしまうと、失敗時に既存を使い続けるという要求が表現できなくなる。

### 更新は有効期間の1/3を切ったら、ただし30日は確保する

閾値は有効期間の 1/3 とし、それが30日を下回る場合は30日とする。ACME が発行する90日の証明書ではどちらも30日になり、失敗し続けても1か月の猶予が残る。

ただし閾値は**有効期間の半分を上限にクランプする**。この上限が無いと、30日より短い証明書は発行された瞬間に更新期限を過ぎていることになり、再試行のループが発行のレート制限を消費し続けるだけになる。上限が効くのは有効期間60日未満の証明書だけで、実運用で使う90日の証明書には影響しない。

### SAN の不足は更新するが、余りは更新しない

必要なホストを SAN が満たしていなければ更新する。逆に SAN が必要より多くのホストを含んでいる場合は更新しない。上位集合はどのホストも変わりなく提供できるので、集合を縮めるためだけに発行し直すのは、どのクライアントからも観測できないことにレート制限を払うことになる。

ホストの照合は X.509 の名前照合そのものに委ねる。手で置いたワイルドカード証明書が個別のホストを満たす、という判断がこれで自然に得られる。ADR 0005 が「手動で用意した証明書は尊重する」と書いた対象には、ワイルドカード証明書が含まれる。

### 失敗の経路では Secret に一切書かない

証明書が手に入ってから初めて Secret に書く。取得に失敗した場合、Secret に対する操作は行わない。削除もしないし、部分的な更新もしない。これが ADR 0005 の必須要件の実装であり、envtest で「3回連続で失敗させても Secret のバイト列が変わらない」ことを確認している。

### 再試行はワークキュー、記録はイベント

再試行はコントローラのワークキューが持つ指数バックオフに委ねる。初回の待ちはミリ秒ではなく30秒から始め、上限は8時間とする。ACME のディレクトリは発行だけでなく失敗にもレート制限をかけるため、失敗直後に間を置かず再試行するのは害にしかならない。上限まで伸びても、30日の更新猶予の中に数十回の試行が収まる。

失敗の回数と理由は Ingress に対する Event として記録する。ADR 0005 は「`status` またはイベント」と書いているが、Ingress の `status` は `loadBalancer` しか持たず、書き込める場所が無い。イベントには連続失敗回数・理由・既存の証明書の有効期限を入れる。「更新に失敗したが、既存の証明書はいつまで使える」が1行で読めることを目的とする。

### 証明書 Secret に ownerReference を付けない

gated は既存の Secret をそのまま引き継ぐ（ADR 0005）。手で置いた証明書に所有者を書き込むと、Ingress を消したときにガベージコレクタがその証明書を道連れにする。所有関係はラベルで表明するにとどめ、削除の権限は持たない。

### 鍵は ECDSA P-256、CSR に CN を入れない

アカウント鍵も証明書の鍵も P-256 とする。クライアント側の互換性は10年前に解決しており、クラスター全体の TLS を終端するプロセスにとってハンドシェイクの費用は安いほうがよい。

CSR の subject は空にする。common name は SAN が言うことを繰り返すだけであり、64文字の制限に引っかかるホスト名を理由なく拒否される経路を作る。

## Consequences

更新の規則が、クラスターを立ち上げずに全分岐を列挙できる形になった。期限ちょうど、SAN の過不足、パース不能、期限切れ、まだ有効でない、といった境界がすべてテーブルテストの1行になる。

「更新すべきか」と「使えるか」を分けたことで、失敗時の挙動が実装の注意深さではなく型の上に現れる。イベントの文面も、既存の証明書が使えるかどうかで書き分けられる。

閾値に有効期間の半分という上限を入れたため、短命の証明書に対する挙動が「常に更新」ではなく「半分で更新」になる。ACME の一部が短命証明書に向かいつつあることを考えると、この上限は将来効いてくる可能性がある。

イベントを記録先に選んだため、失敗の履歴はイベントの保持期間（既定1時間）を超えて残らない。長期の傾向を追うにはメトリクスが要る。今は持たない。

ownerReference を付けないため、Ingress を消しても証明書の Secret は残る。手で消すことになる。誤って自動発行の証明書を消してしまう事故より、手動の証明書を自動で消してしまう事故のほうが取り返しがつかないと判断した。
