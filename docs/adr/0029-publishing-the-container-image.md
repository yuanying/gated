# 0029. イメージは ref の名前で ghcr へ公開する

- Date: 2026-08-22
- Status: Accepted

## Context

gated を実際のクラスターへ配備することになった。クラスターが引けるイメージが要る。

手元から push すれば今日は動く。しかし後になって「動いているイメージがどのコミットから焼かれたか」を答えられない。押した人の作業ツリーには、コミットされていない変更があったかもしれず、それを確かめる方法が残らない。イメージは、リポジトリにあるコミットから、記録の残る場所で焼かれる必要がある。

一方で、イメージの公開は ADR 0026 が引いた線に触れる。0026 は次の2つを決めている。

- CI は秘密情報を一つも要求しない。fork からの PR でも全ジョブがそのまま走る
- ワークフローの権限は既定で読み取りのみとし、どのジョブもそれを広げない

レジストリへの push は、認証を要し、書き込みの権限を要する。そのまま書けば `no-live-layer` の検査が落ちる。検査は `.github/workflows/` を全文検索し、`secrets.` への参照を見つけたら失敗するからである。

ここで検査を緩めるのは容易だが、そうすると検査は「緑であること」の意味を失う。先に、守るべきものが何だったのかを言葉にする必要がある。

## Decision

### 公開先は ghcr.io/yuanying/gated

ソースが GitHub にある以上、同じ場所のレジストリなら認証は実行ごとに発行されるトークンで済む。別のレジストリを使えば、保存された資格情報をこのリポジトリに置くことになり、それは下で守ると決めたものを壊す。

### タグは「そのイメージを作った git ref の名前」

規則は1つだけである。

| 何を push したか | 付くタグ | 誰が使うか |
|---|---|---|
| `main` ブランチ | `main` | 手元での確認。動き続けるので pin してはならない |
| `vX.Y.Z` の git タグ | `vX.Y.Z` | 配備側が pin するのはこれ |

タグの文字列と ref の名前が同じなので、動いているイメージから ref を引くのに変換規則を知る必要がない。

`latest` は公開しない。動くタグを2つ持つ理由が無く、`latest` は「どの ref から来たか」を答えられない唯一のタグになる。`config/manager/deployment.yaml` が `:latest` を書いていたが、これは公開されないタグを指していたので `:main` に改める。配備するときは overlay が版タグで上書きする（ADR 0023）。

版タグの元になる git タグは人が打つ。main が緑であるコミットに対して打つ。publish 自体は CI の結果を待たない（後述）。

### プラットフォームは linux/amd64 のみ

配備先クラスターの arm64 ノードはすべてスケジュール不可に設定されており、gated が載る先は amd64 だけである。QEMU で arm64 を焼く時間を今払う理由が無い。

ただし増やせない形にはしない。ビルドは buildx を通し、プラットフォームは一覧として書く。Dockerfile は既にビルダーから対象の OS とアーキテクチャを受け取るので、増やすときは一覧に1行足すだけである。

### publish は CI とは別のワークフローに置く

同じファイルに同居させない。理由は4つある。

- **trigger が違う。** CI は PR ごとに走る。publish は push だけで走り、PR では走らない
- **権限が違う。** `ci.yml` の先頭にある読み取りのみの宣言は、「このファイルにあるものは何も書かない」という一文である。同じファイルに書き込むジョブを置くと、その一文は「ジョブごとに見ろ」に変わる
- **fork の PR で走る集合と走らない集合を、ファイルの境界と一致させたい。** どちらが走るかを、trigger を読み比べずに判断できる
- **publish は判定ではない。** CI が赤ければ PR は止まる。publish が赤くてもイメージが出ないだけで、判定は何も変わらない

### 権限は publish の唯一のジョブにだけ広げる

ワークフローの先頭は読み取りのみのままにし、パッケージへの書き込みはジョブに書く。書ける主体が1つであることが、ファイルを開いた位置から見える。

### fork の PR で publish が走らないことの保証は trigger にある

publish の trigger は push だけである。fork からの PR は、このリポジトリに push イベントを起こさない。fork 内での push はその fork のリポジトリで走り、そこで発行されるトークンは fork のパッケージにしか届かない。

保証はワークフローの中身ではなく trigger の集合にある。したがって危ないのは、trigger に `pull_request_target`（fork のブランチを、base リポジトリのトークンを持ったまま checkout する）が足される場合である。これを検査に足す。今は誰も必要としていないので、禁止しても失うものが無い。

### 検査を「`secrets.` があるか」から「保存された秘密情報を読むか」に書き直す

ADR 0026 の検査 2 が守っていたものを2つに分ける。

- **守るもの A** — PR の判定に、保存された秘密情報を要求しない。fork からの PR が判定を丸ごと走れること
- **守るもの B** — live 層の資格情報は、どのワークフローにも渡さない（ADR 0025）

「`secrets.` という文字列がワークフローに一切現れない」は、A と B を実装した結果として成り立っていた性質であって、A でも B でもない。

実行ごとに GitHub が発行するトークンは、保存された秘密情報ではない。ジョブの寿命しか存在せず、`permissions` の宣言が上限を決め、このリポジトリの外の何にも届かない。実在の認証局にも DNS ゾーンにも到達できない。fork からの PR にも（読み取りとして）渡される。A も B も、これを許して壊れない。

そこで検査を4つに分ける。

| 検査 | 何を見るか | 例外 |
|---|---|---|
| live 層を走らせるか | live 層のターゲット、`live` タグ付きのテスト実行 | 無し |
| live 層が読む値を名指しするか | 環境から取る値の名前 | 無し |
| 保存された秘密情報を読むか | 秘密情報への参照 | 実行ごとに発行されるトークンだけ |
| fork のコードをこのリポジトリの権限で走らせるか | fork のブランチを base の権限で checkout する trigger | 無し |

例外は1つだけで、検査の中に名前が書いてある。例外を持たない3つは、publish の追加によって何も変わっていない。

**すり抜けられる書き方をしない。** 同じトークンは `github` コンテキストからも読め、そう書けば検査は何も言わない。それはしない。publish は秘密情報としての名前で書き、検査はその名前を名指しで許す。すり抜けた検査は、緑であることに意味が無い。

### 生成物は run のサマリから辿れる

押したタグ、ダイジェスト、元のコミット、パッケージのページを run のサマリに書く。ログを開かずに、何がどこへ出たかが分かる。

## Consequences

ADR 0026 の「CI は秘密情報を一つも使わない」は、「PR の判定は保存された秘密情報を要求しない」に狭まった。0026 の当該節と検査の記述を、この ADR に合わせて改めた。

権限が読み取りのみでないワークフローが1つできた。今後ワークフローを足す人は、どちらのファイルに置くかを判断することになる。判断の材料は上の4点である。

main への push ごとにイメージが1つ焼かれる。CI の結果を待たないので、テストの通らないコミットから焼かれた `main` タグも出る。`main` は pin する対象ではないと決めてあるので、これは意図した動作である。判定が要るのは版タグのほうで、そこには「main が緑であるコミットに打つ」という人の手順がかかる。手順である以上、破れる。破ったときに気づく仕組みは今は無い。

amd64 しか出ないので、arm64 のノードに載せようとすると引けない。どのノードに載るかは配備側の責任になる。

`latest` を公開しないため、`kubectl apply -k config/default` をそのまま実行すると `main` の、つまりその時点の main のイメージが動く。版を選ぶには overlay で上書きする。

Renovate は github-actions のグループでこの新しいワークフローの action も追う（ADR 0027）。`config/manager` のイメージを Renovate が見ないという設定はそのままだが、その理由は「問い合わせるレジストリが無い」ではなくなった。理由を書き直した。
