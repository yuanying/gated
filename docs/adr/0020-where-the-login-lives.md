# 0020. ログインをどこに置き、handoff を一度きりにする方法

- Date: 2026-08-21
- Status: Accepted

## Context

ADR 0003 は、ログインの入口を中央認証ホスト1つに集約し、保護対象のホストへ戻る際に「そのホスト限定の Cookie」を発行すると決めた。ADR 0018 は、そこへ送るリダイレクトの組み立て方と、戻り先の安全性を検査するのは戻す側だという分担を決めた。

決まっていないことが3つ残っている。

1つは、ログインのハンドラをリクエスト経路のどこに置くかである。中央認証ホストには Ingress が向いていないことがありうるし、保護されたホストの `/__gated/callback` は認可を通してはならない。認可を通せば、ログインしていないから通れず、ログインへ送られ、その戻り先がまた同じ場所になる。

もう1つは、中央認証ホストから保護対象ホストへ何を渡すかである。ホストが違うので Cookie は使えず、渡せるのは URL に乗るものだけになる。URL に乗るということは、ブラウザの履歴に残り、場合によっては referrer にも乗るということである。それを拾った者が保護対象ホストの Cookie を手に入れられるなら、集約した意味が薄れる。

3つ目は、セッションの有効期限をどう与えるかである。ADR 0003 は「短めに設定する」とだけ書いた。

## Decision

### ログインはルーティングより前に置く

リクエストは、ルーティング・認可・プロキシの手前でログインのハンドラに一度渡す。ここで引き取るのは次の2つだけで、それ以外はそのまま後段へ流す。

| ホスト | パス | 引き取るもの |
|---|---|---|
| 中央認証ホスト | `/__gated/` 以下 | ログインの開始と、Identity Provider からの戻り |
| それ以外 | `/__gated/callback` | handoff を受け取って Cookie を発行する |

前に置くことで、中央認証ホストは Ingress がバックエンドを持っていなくても応答できる。TLS の証明書だけは必要なので、中央認証ホストを `spec.tls` に含む Ingress は要る。

中央認証ホストの `/__gated/` 以外は後段へ流す。集約先のホストが他のものも配信している構成を壊さないためである。

Identity Provider の戻り先は `/__gated/idp/<プロバイダ名>/callback` とする。プロバイダごとに別のパスにするのは、あるアプリケーション向けに発行された認可コードが別のアプリケーションのコールバックで交換されることを、経路の形として起こらなくするためである。登録する URL はプロバイダあたり1つのままで、ADR 0003 が得ようとしたものは変わらない。

### handoff はブラウザに結び付け、使うと消える

保護対象ホストは、中央認証ホストへリダイレクトする前に、そのホスト限定の短命な Cookie に乱数（nonce）を置く。URL に乗せるのはその**ダイジェスト**だけで、中央認証ホストはそれを預かって handoff トークンに封じ、保護対象ホストの callback がダイジェストと手元の nonce を突き合わせる。

これで handoff は「そのブラウザでしか使えない」ものになる。URL から拾った者は nonce を持たないので、トークンだけでは何もできない。callback は突き合わせの前に nonce の Cookie を消すので、同じブラウザでの2度目も通らない。**サーバ側に何も置かずに使い捨てになる**のはこの消去による。

nonce の Cookie が無い状態で `/__gated/login` に来た場合——ブックマークや履歴からの直接アクセス——は、戻り先として指定されたホストへ送り返す。そこで改めてログインが始まり、今度は nonce が置かれる。行き止まりのエラーにしないためであり、送り先はルーティングテーブルにあるホストに限られているので、これがオープンリダイレクトになることはない。

handoff の寿命は30秒とする。URL に乗るものなので、履歴に残ってからの窓を最小にする。

Cookie を親ドメインに広げる案（ADR 0003 が採らなかったもの）や、handoff を長寿命にして使い回す案は採らない。前者は ADR 0003 の決定そのものであり、後者は上の結び付けを無意味にする。

### 中央認証ホスト自身はセッションを持たない

中央認証ホストは自分用の Cookie を発行しない。保護対象ホストを1つ訪れるたびに Identity Provider との往復が発生する。

自前のセッションを持てば往復は省けるが、そのセッションは「どのホストへでも handoff を出せる資格」になる。中央認証ホストの Cookie が漏れれば全ホストが開くことになり、Cookie をホスト単位に閉じ込めた ADR 0003 の判断と噛み合わない。往復といっても Identity Provider 側にセッションがあるのが普通で、体感はリダイレクトが1往復増えるだけである。

### CSRF は state と Cookie の突き合わせで防ぐ

`/__gated/login` は乱数を1つ作り、それを中央認証ホスト限定の Cookie に置き、同じ値を署名付きの state パラメータに入れて Identity Provider へ渡す。戻ってきたときに両者を定数時間で比較し、一致しなければ拒否する。state は使うと消す。

state には戻り先とプロバイダ名も入れる。どちらも署名の中にあるので、戻り道の途中で書き換えられない。

### セッションの寿命は起動フラグで与える

`--session-ttl` を足し、既定を12時間とする。ADR 0009 の分類でいえば「どこで動かしても同じでよい値」なので既定を持たせてよい。環境ごとに縮めたい場合にフラグで縮められる。

## Consequences

ログインの経路が認可の判定を一切通らないので、ADR 0018 が作った判定の呼び出し口は1つのままである。認証が増えたことで変わったのは、そこへ渡る主体が空文字でなくなったことだけである。

`/__gated/` 以下は gated が予約したままで、予約の範囲は ADR 0018 が書いたときから広がっていない。

handoff を拾われても使えないので、URL に識別情報を乗せることの主な危険が消える。代償として、Cookie を受け付けないブラウザではログインが完了しない。従来からセッション Cookie が必須なので、新しい制約ではない。

nonce の Cookie は最後に始めたログイン1つ分しか保持しない。同じホストへのログインを複数のタブで同時に始めると、先に始めたほうが完了できず、やり直しになる。滅多に起きず、起きても1回のリダイレクトで回復する。

中央認証ホストにセッションを持たせないため、保護対象ホストを複数まわると Identity Provider への往復がその数だけ発生する。Identity Provider 側のセッションが効いている限り、利用者に見えるのは一瞬のリダイレクトである。
