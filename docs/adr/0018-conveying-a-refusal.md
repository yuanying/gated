# 0018. 拒否をどう伝えるか、主体をどこから受け取るか

- Date: 2026-08-21
- Status: Accepted

## Context

ADR 0002 は、未ログインで拒否された相手をログインへ誘導し、ただし `Accept` が HTML を求めていない場合は 401 と `WWW-Authenticate` を返すと決めた。ADR 0007 は、その判断を純関数の外側で行うことも決めた。判定は「許可・拒否・要ログイン」の3値までで、それが何番のステータスコードになるかは知らない。

外側で決めるとして、決めることが3つ残っている。相手がブラウザかどうかを何で見分けるか、`WWW-Authenticate` に何を書くか、そしてログインへ送るときの行き先をどう組み立てるか。

もう1つ、認証（ADR 0003）はまだ無い。主体を確定させる仕組みが入るまでの間、認可はすべてのリクエストを未ログインとして扱うことになる。あとから差し込む場所を決めておかないと、認証が入る段になって認可の呼び出し側を書き換えることになる。

## Decision

### ブラウザかどうかは `Accept` が HTML を名指ししているかで決める

`Accept` の中に `text/html`、`application/xhtml+xml`、`text/*` のいずれかがあり、それが `q=0` で否定されていなければブラウザ扱いとする。

`*/*` はブラウザ扱いにしない。curl も、大半のクライアントライブラリも `*/*` を送る。これをブラウザと読むと、保護されたサービスと話すプログラム全部が、読めもしないログイン画面へ送られる。ヘッダが無い場合も同じ扱いにする。

gated が返す表現は1つしかないので、これは本来の内容交渉ではない。相手が人間かどうかの、粗いが外れにくい見分け方として使う。

### ブラウザには 302、それ以外には 401 と BASIC のチャレンジ

ブラウザには 302 で中央認証ホストへ送る。応答は相手によって変わるので、キャッシュを禁じる。

それ以外には 401 と `WWW-Authenticate: Basic` を返す。realm は gated 自身の名前とし、どの環境かを示す語を入れない。

Bearer のチャレンジは返さない。`WWW-Authenticate: Bearer` を見たコンテナレジストリのクライアントは、そこに書かれた realm へトークンを取りにいく手順を始める。gated はその手順を実装していない。ADR 0004 が守りたかったのは `docker login` を変えずに使えることであり、そのために必要なのは BASIC のチャレンジだけである。

### ログインの行き先は、この段階では組み立てるだけ

中央認証ホスト（ADR 0003）の `/__gated/login` へ、戻り先を `next` クエリに入れて送る。戻り先は常に https の絶対 URL とする。平文のリスナはバックエンドへ何も転送しない（ADR 0013）ので、保護されたリソースへ戻る道は TLS しかない。

パスは `/__gated/` で始める。アプリケーション側の経路と衝突しないためであり、この接頭辞の下に戻り先を受け取る `/__gated/callback` も入る。この2つの名前は、リダイレクトを組み立てる側と、それを受け取るハンドラの両方が同じものを指す必要があるので、片方が勝手に決めない。

戻り先が安全かどうかは、ここでは検査しない。検査するのは戻す側、つまり中央認証ホストと callback であり、ルーティングテーブルが知っているホストに限る（オープンリダイレクト対策）。組み立て側で検査しても、`next` を書き換えて直接叩かれれば意味がない。

リクエストのホストが中央認証ホスト自身だった場合は、リダイレクトせず 401 を返す。自分自身へ送るとブラウザが諦めるまで往復し、理由は何も表示されない。

### 主体は interface から受け取る

認可のミドルウェアは、リクエストから主体を答える interface を1つ持つ。この段階では未設定で、すべての呼び出し元が未ログインになる。セッション Cookie（ADR 0003）も、Bearer と BASIC のトークン（ADR 0004）も、この1つの口を埋める形で入る。

主体を決めた後は、それを後段から読めるようにしておく。同じリクエストで2度身元を確かめる実装を避けるためである。

## Consequences

ブラウザは今までどおりログイン画面に着き、プログラムは 401 を受け取って自分で判断できる。`docker login` は変更なしに BASIC のチャレンジを受け取る。

`Accept` に頼っているので、HTML を要求しないブラウザ経路——`fetch` で始まる呼び出しなど——は 401 になる。これは正しい側の失敗で、そこで 302 を返せばログイン画面の HTML が API の応答として返ることになる。

`/__gated/` 以下のパスは gated が予約したことになる。アプリケーションが同じ場所を使っていれば衝突するが、その場合の判断は衝突が起きてからでよい。

認証が入るまで、保護されたリソースは誰にも開かない。`system:unauthenticated` に許した範囲だけが通る。これは段階を分けた結果として正しい状態であり、認証が入った時点で残りが通り始める。
